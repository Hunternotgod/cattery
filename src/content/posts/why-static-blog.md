做个人博客有很多种方式。WordPress 功能齐全，Notion 发布足够省事，Next.js 看起来也很现代。最后我还是选了最朴素的一种：**静态站**。

## 静态站解决的是什么问题

静态站的核心很简单：构建时把 Markdown 生成 HTML，部署时只需要提供文件，不需要数据库，也不需要一直运行的后端进程。

这带来几个直接的好处：

- 页面打开快，服务器压力小
- 没有数据库和登录后台，攻击面小
- 内容是可迁移的纯文本
- 托管便宜，个人博客的流量通常用免费额度就够

对一个以文字为主的博客来说，这些优点比“功能多”更重要。

## 为什么是 Astro

Astro 默认输出静态 HTML，同时保留了组件化开发的能力。需要交互时可以加一点客户端脚本，不需要时页面里几乎没有 JavaScript。

文章放在 `src/content/posts/`，每篇文章就是一个 Markdown 文件：

```yaml
---
title: "文章标题"
description: "一句话摘要"
pubDate: 2026-10-20
tags: ["随笔"]
---
```

构建命令也很直接：

```bash
npm run build
```

生成的 `dist/` 目录可以直接上传到任何静态托管服务。

## 它不适合什么

静态站不是万能的。如果你需要：

- 多人协作编辑
- 复杂的会员和权限
- 大量实时交互
- 在浏览器里直接管理数据库

那它可能不是最合适的选择。个人博客通常不需要这些，所以这个取舍是划算的。

## 国内访问的考虑

静态站只是“怎么生成”，还没有回答“放在哪里”。

如果读者主要在国内，托管位置和域名备案会直接影响体验。我的计划是先用默认域名把内容写起来，确定长期更新之后，再买域名、完成备案，绑定国内静态托管。

先让内容跑起来，再逐步补基础设施。这样不容易在一开始就被配置和费用劝退。
